## 🎯 목적에 맞는 도구 선택: IDE

세상엔 Visual Studio, VS Code, IntelliJ, Eclipse 등 수많은 **IDE**(Integrated Development Environment, 통합 개발 환경)가 존재합니다.

<a href="https://survey.stackoverflow.co/2025/technology#most-popular-technologies-dev-envs"><img src="./src/1. 환경세팅과 전반적인 이야기/IDE-survey.png" width="60%"></a><br>


이 모든 걸 다 알아야 할까요? 당연히 아닙니다.

중요한 것은 **'내가 무엇을 만들고 싶은지'에 따라 올바른 도구를 선택하는 것**입니다.

예를 들어볼까요?

- "나는 가볍고 빠른 코드 편집 및 실행이 필요해!" → **Visual Studio Code, Sublime Text, 메모장 ...**
- "나는 게임 개발을 하고 싶은데?" → **Unity, Unreal Engine ...**
- "나는 안드로이드 앱을 만들고 싶어!" → **Android Studio**

이처럼, 우리의 목적에 따라 사용해야 할 도구는 명확하게 달라집니다.

지금 우리의 목적은 **WPF를 이용한 윈도우 데스크톱 앱 개발**입니다.<br>

그리고 이 목적을 위한 가장 강력하고 표준적인 도구가 바로 **Visual Studio**입니다.

이제부터 왜 우리가 Visual Studio를 선택해야만 하는지, 그 이유를 자세히 알아보겠습니다.

### 왜 Visual Studio를 사용해야 하는가?

이미 개발에 익숙해지신 분들은

*"VS Code에 익숙한데, 무조건 Visual Studio를 설치해야 하나?"*

라고 충분히 고민할 수 있습니다.

실제로 압도적으로 많이 사용하는 IDE인 VS Code와 비교해서, **왜 WPF 개발에서만큼은 Visual Studio를 사용해야 하는지**에 대해서 알려드리겠습니다.

결론부터 딱! 말씀드리면, 아래의 **세 가지 결정적인 차이** 때문입니다.

#### 1. '조립 PC'가 아닌 '완제품 PC'

VS Code, 정말 가볍고 좋은 툴이죠.<br>
원하는 기능(Extension)을 이것저것 설치해서 '나만의 개발 환경'을 만들 수 있다는 게 가장 큰 장점이고요.<br>
이건 마치, 내가 원하는 부품을 하나하나 사서 조립하는 조립 PC와 같아요.

하지만 **Visual Studio는 C#과 .NET 개발에 필요한 모든 것을 품고 태어난 완제품 PC**입니다.<br>
우리가 WPF 앱을 개발하기 위해 필요한 **컴파일러, 디버거, 각종 편의 기능들이 처음부터 완벽하게 세팅**되어서 *"님은 그냥 쓰기만 하세요"* 하는 상태인 거죠.

물론 VSC를 만지작만지작 하고, 잘 세팅한다면 사용 할 수는 있겠지만, **귀찮잖아요?ㅎㅎ**<br>
게다가, **이미 가장 안정적이고 검증된 IDE**가 있으니, 편하기도 하고요!

#### 2. '미리보기'와 '디자인'의 넘사벽 차이 (이게 제일 중요해요! ⭐⭐⭐)

*"VS Code도 확장 프로그램 깔면 UI 미리보기 되는데요?"*

네, 맞아요.<br>
하지만 그건 말 그대로 **미리보기, Preview**일 뿐이에요.<br>
내가 짠 코드가 어떻게 생겼는지 보여주는 1차원적인 기능이죠.

하지만 Visual Studio의 **비주얼 디자이너**는 차원이 다릅니다. 이건 양방향이에요.<br>
화면에서 버튼을 마우스로 끌어다 놓으면 → 코드가 자동으로 써져요.<br>
코드에서 버튼 사이즈를 바꾸면 → 화면의 버튼이 바로 커져요.

즉, **더 쉽고 편하게 프로그램을 디자인**이 가능해집니다.<br>
이건 단순히 코드를 보여주는 미리보기와는 비교할 수 없는, 개발 속도를 말도 안 되게 올려주는 넘사벽 기능입니다.

#### 3. '파일 탐색기'와 '설계도'의 차이

VS Code는 우리 프로젝트를 '파일과 폴더의 모음'으로 봅니다. 똑똑한 '파일 탐색기' 같죠.

하지만 Visual Studio는 우리 **프로젝트의 구조**, 즉 **파일 간의 관계를 완벽하게 이해하고 있는 설계도**를 보는 것에 가깝습니다.

WPF 프로젝트는 그냥 코드 파일 몇 개가 전부가 아니라, UI 파일(.xaml), 코드 파일(.cs), 설정 파일, 리소스 등이 복잡하게 얽혀있거든요.

Visual Studio는 이 설계도를 기반으로 *"아, 이 버튼을 누르면 저쪽 코드의 이 함수가 실행되어야 하는구나!"* 하는 걸 다 알고 있기 때문에, **훨씬 더 안정적으로 프로젝트를 관리**해 줍니다.

자, 이제 왜 우리가 VS Code가 아닌 Visual Studio를 써야 하는지, 느낌이 확실히 오시죠? 😉
